|---|---|---|---|
| AP-01 冻结实际解析闭包 | Capture 深拷贝实际读取的 bytes 并固定目录观察，scan/compile 复用 parser；直接重新读取来源会让身份与产物消费不同内容，archive 的下一次读也可能覆盖旧借用。 | `A-CAPTURE`；**Derived**。一致输入是义务，冻结 VFS 后重跑 parser 是当前实现选择。 | **Fact**：`ModelParser.capture`、`CapturedSourceData.freeze`、`RawModelImporter.convert`；`ModelParserTest.captureCopiesBorrowedFilesFreezesDirectoriesAndNeverFallsBack` 与 `captureClosesEveryOwnedCopyExactlyOnce` 明确断言修改后不回读及独立副本关闭。[capture 理由](../../architecture/model-management/design-rationale.md#capture-复用同一解析路径)。不保证整个可变文件系统在同一个物理时刻快照。 |
| AP-02 分层准入与逐块验证 | Metadata prefix 建立 identity/Manifest 描述，容器 reader 独占容器版本准入，schema reader 复用无状态开发版本门禁；实际 chunk 仍核对 size、hash 和适用解码。删除后，目录可见会被误当作内容有效，开发版本也可能被未来放宽的稳定版策略误接纳，损坏或跨表示 bytes 可进入资源构造。 | `D-META`、`D-VERIFY`、`D-IDENTITY`、`D-FREEZE`；**Essential**，由按需访问、精确表示与开发制品不可推断兼容的产品契约直接要求。 | **Fact**：`VersionCompatibility`、`AssetContainerReader`、`ModelFileView.readMetadata`、`ChunkDecoding.decodeZstd/validateDirectPayload`；`VersionCompatibilityTest` 覆盖两侧 marker、大小写/包含、稳定版委托和 fail-closed。[分层验证](../../architecture/asset-pipeline/container-and-validation.md)。版本门禁是纯函数，不新增状态、owner、生命周期或恢复分支；结构/当前 profile 检查不能充当完整标准 conformance。 |
| AP-03 Raw PNG 的用途驱动重编码与失败回退 | Raw 转换复用合法的 JPEG/WebP/AVIF 等既有压缩表示，只让 PNG 进入用途策略；编码成功即采用结果，即使制品变大，只有可处理的 codec I/O 失败才保留原图。删除格式门禁会重复处理既有压缩表示，删除失败回退会把可用输入变成转换失败。 | `D-IMAGE` 与 `A-IMAGE`；**Derived**。用途保真义务不可删，输入门禁、codec/尺寸策略和失败回退是可替换方案；legacy 解码期图片归约另归 NR-17。 | **Fact**：`RawImageCompressor.compress`、`ImageEncoder`；`RawImageCompressorTest.skipsUnsupportedFormatsWithoutCallingTheCodec`、`replacesPngEvenWhenEncodedRepresentationIsLargerAndForwardsLimits` 与 `keepsTheOriginalWhenRecompressionFails` 分别断言复用、较大结果替换和失败回退。[处理位置](../../architecture/asset-pipeline/conversion-and-export.md#图像处理的位置)。策略效果与成本证据见 [Q-04](open-questions.md#q-04)。 |
| AP-04 连续页面需求与迟到结果处置 | Screen 保存真实页面身份、前项持续与当前起点；内部重建交接同一意图，真实换页/关闭才撤需求。缺件且前项短时，当前连续 >0.7 秒才提交同一个 presentation action；同步/异步失败都终态，迟到结果不能复活页面。删除会让短命页面发包、内部重建永不满足门槛或需求悬挂。 | `A-PAGE`、`A-CONTINUOUS-DEMAND`；**Derived**。GUI 寿命短于共享资源且产品要求过滤短命意图。 | **Fact**：`CatalogDemandTracker`、`ClientAssetRepository.Batch.submit/failAll`、`PlayerModelScreen.closePage`；[页面 owner](../../architecture/client-presentation/README.md#页面与资源-owner)。Preview miss 仍归同一 page action；页面终态不回滚合法独立 cache。 |
| AP-05 Preview-first 与 hover-gated cache-only 3D | 卡片先查有效图片、Ready 与 cache-only target；只有连续 hover 同一模型 >0.3 秒才尝试 offline target，remote body miss 不发网络且不污染 normal acquire。改用普通 acquire 会让浏览驱动下载，构造即离线 bake 会让无需求卡片消耗资源。 | `A-PREVIEW`、`D-JOIN`、`A-CONTINUOUS-DEMAND`；**Derived**。展示体验与按需加载是义务，offline probe/hover state 是当前方案。 | **Fact**：`CatalogModelCardState`、`ClientModelRenderTargetManager.getOrStartCached/getOrStartOffline`；[cache-only 边界](../../architecture/model-management/storage-and-cache.md)。真实 3D 体验收益和最坏 target 成本仍未量化。 |
| AP-06 转换 staging 与重开验证 | Raw/legacy 转换先形成独立 staging，验证 identity、逻辑 payload 和存储描述后才进入 converted object/目录 candidate；失败清理本次半成品。只删门禁会把“转换过程成功”当成“当前容器可读”，或暴露部分产物。 | `A-ONE-ARTIFACT`、`D-FREEZE`、`D-SOURCE`；**Derived**。跨输入格式统一出口带来产物交接；来源只读与完整内容仍是独立要求。 | 架构事实见[转换出口](../../architecture/asset-pipeline/conversion-and-export.md#发布与失败)及[单向投影](../../architecture/asset-pipeline/conversion-and-export.md#历史输入的单向投影)；验证入口 `LegacyModelImporter.stage`、`RawModelImporter.convert`、`ConvertedObjectStore`。保留 staged 容器再读是当前策略，未以文档替代全部 golden/真实导入测试。 |
| AP-07 实际来源准入与 schema 分离 | Schema reader 接受合法无图容器；Catalog 只对实际 direct 成品要求声明且完整解码内嵌 preview，raw/builtin/legacy 内部结果允许缺图。来源由 resolver 调用链固定，不能由扩展名、`origin_ver` 或 cache 猜测。删除分层会拒绝合法内部来源，或让缺图 direct 绕过产品门禁。 | `A-DIRECT-ADMISSION`、`D-SOURCE`；**Derived**。按来源准入是产品选择，单独 policy gate 是当前方案。 | **Fact**：`DirectContainerAdmission.requireEmbeddedPreview`、`ModelSourceResolver.resolve/resolveMaterialized`；[preview/export](../../architecture/asset-pipeline/conversion-and-export.md#preview-取得与显式-export)。完整来源矩阵与跨平台媒体仍未验。 |
| AP-08 弱关联 preview cache 与完整 export | 内嵌图优先；独立图只按 `ContainerId` 存储，坏读不删除，验证后原子覆盖。Client tick 的单一有限 operation admission 连续覆盖 probe、Ready/Flight 或 detached load、host fact、编码/存盘与 export，跨域 callback 只写容量为 1 的 owned fact slot，tick 观察终态后才释放；专服已有图片 export 由 server tick 接纳一项完整 worker。显式 export 复制已验证 stored chunks、保留 `ModelId`/作者图、必要时嵌图并重算 `ContainerId`，重开 direct 验证后提交。删除独立 cache 会重复取得图片；把 cache 回写容器会制造身份/目录循环；删除总 admission 会使页面 miss 或重复命令无界保留 candidate/pixels/source。 | `A-PREVIEW-CACHE`、`A-WORK`、`D-FREEZE`、`D-SOURCE`；**Derived**。日常不改容器、弱关联和完整 export 是产品边界；当前统一 admission 是满足主循环与有限在途义务的可替换方案。 | **Fact**：`ClientPreviewGenerator.tick`、`ClientModelService.tick`、`PreviewRenderHost`、`PreviewStore`、`ModelExporter.export`、`ModelExportService.ServerRuntime`、`ServerModelService.tick`；[preview/export](../../architecture/asset-pipeline/conversion-and-export.md#preview-取得与显式-export)。Client 现为 16 active/32 pending/每 tick 4 次接纳，server export 为 8/16/4；共享 worker/render owner 与 target 能力，无第二 scheduler、截图 RPC、后台补写或图片版本 authority。owner-pause/capacity/terminal 有局部测试；真实画面、命令与 cold/warm 成本未验。 |
| AP-09 音频投影与双阶段验证 | Raw 与 legacy producer 把受支持的单一 Ogg Vorbis/Opus stream 投影为同一 current descriptor/direct chunk；metadata admission 核对结构和媒体解释，目标声音取得或 M2 materialization 再验证完整 bytes/codec 闭包，export 原样复制并重开复验。删除统一 profile 会让 producer/consumer 对 codec、frame 或存储形状分歧；把 M2 或播放验证并入 catalog 浏览会预读全部声音。 | `D-SOUND`、`D-MIGRATION`、`D-JOIN`、`D-CHUNKS`；**Derived**。声音可播放、单向迁移和按需内容是义务，双阶段落点是当前方案。 | **Fact**：`RawModelAssembler`、`SupportedAudioProbe`、`SoundStreamView`、`LegacyModelImporter`、`BuiltinModelMaterializer`、`ModelExporter`；[音频转换](../../architecture/asset-pipeline/conversion-and-export.md#音频内容转换)。独立 fixture 已覆盖 raw directory/archive、current export/reopen 与 legacy projector；真实 v1/v2/v3 包装和游戏来源矩阵未验。 |
