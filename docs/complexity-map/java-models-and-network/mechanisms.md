共享依据：产品选择见[模型生命周期](../../product-decisions/requirements/req-authoritative-model-lifecycle.md)、[按需分发](../../product-decisions/requirements/req-bounded-model-distribution.md)；实现取舍分别见[模型理由](../../architecture/model-management/design-rationale.md)和[网络理由](../../architecture/network/design-rationale.md)。

|---|---|---|---|
| MN-01 增量 candidate 与单点发布 | Scan 逐项完成验证，owner tick 在处置预算内把完成项合成一致 index/snapshot；坏新项不替换旧项，根不完整时不确认删除，已发布成功不回滚。删除完整合成会让消费者看到索引/内容混合，恢复整次 barrier 又会让慢项阻挡有效内容。 | `D-RELOAD`、`D-CATALOG`；**Essential**，完整条目与一致当前目录直接服务产品义务。 | **Fact**：`ReloadableModelCatalog.ActiveScan.tick/publish`、`CatalogReconciler.resolveInput/mergeCandidate`；[reload](../../architecture/model-management/reload-and-publication.md)。冲突由首个完成验证并被接纳的候选占用，不新增持久赢家。 |
| MN-02 Publication、activation、Ready 分离 | Lean collection authority 先提交，entry 验证 metadata 后进入 Ready 目录，目标资源继续按需取得；替换 publication 取消旧 Pending metadata，复用适用的 terminal tuple。删除会把坏 entry 扩成整体失败或把 metadata 当完整 target。 | `D-JOIN`、`D-CHUNKS`、`A-NOTIFY`；**Derived**，分阶段使用是产品义务，当前 snapshot/activation owner 是实现选择。 | **Fact**：`ClientSessionRuntime.applyCollectionResult/completeActivation`、`RemoteCatalogActivation`；[catalog sync](../../architecture/network/catalog-sync.md)。Authority 先提交，通知失败不回滚事实；没有 ACK/history 来保证即时收敛。 |
| MN-03 同源本地替代与 remote exact | Publication identity 和实际 representation 分别保留；远端精确匹配，本地已验证同 ModelId 可替代。删 exact 校验会混块，删本地替代会重复下载已有同源内容。 | `D-IDENTITY`、`D-REUSE`；**Essential**，两种等价关系是明确产品选择。 | **Fact**：`RemoteCatalogActivation.activateLocal/activate/startMetadata`；[身份决策](../../product-decisions/decisions/model-identity.md)。具体候选优先序可变，不需要第三种长期业务身份。 |
| MN-05 精确读取实例与原子 cache 提交 | Direct 直接读取只读原件，runtime 为本次来源建立单向 Corrupted 实例；每次读在同一句柄核对长度/range/hash。Remote/精确 converted 坏读不删除，验证后原子替换且失败保旧。删实例排序会让已提交坏来源继续起读；删完整提交会发布半份或错表示。 | `D-EXACT`、`D-SOURCE`、`D-REUSE`、`D-HOLD`；**Derived**。未来读取可失败、已验证资源独立有效和精确 cache 发布是明确边界，实例/atomic helper 是当前方案。 | **Fact**：`RuntimeContentStore`、`FileChunkDataSource`、`RemoteModelStore.publishAtomic`、`ConvertedObjectStore`；[storage](../../architecture/model-management/storage-and-cache.md)。Direct 副本及专属 shared-writer 消费者已退出；MN-22 的物理路径约束与 NR-05 baked 序列化仍独立。 |
| MN-06 Ready 可达性、独立 lease 与 unused LRU | 精确 content/profile Ready 保存 cache 引用和 consumer 数；最后 consumer 退出进入 30/60 unused LRU，再取得时退出 unused，超限只撤 cache 引用。任一 consumer 物理 close 会销毁其他实体使用的 target；按对象 identity、idle 或 lease 数计数会误复用或误淘汰。 | `D-HOLD`、`A-RESOURCE`；**Derived**。独立消费者安全与 30/60 驻留是产品义务，可达性/LRU 表示是当前方案。 | **Fact**：`ModelRenderTargetCache.acquire/release/trimUnused`、`ResourceLease`；[所有权](../../architecture/model-management/ownership-and-lifecycle.md)。Default 由 required lease 持有，不用 pin/preload；物理回收无同步上界。Pending 取消另归 MN-17。 |
| MN-07 Domain 有限工作与 owner-tick 提交 | Catalog、client/server runtime 各自接纳完整 worker-safe 有限链，worker 不等网络/host/其他 worker；terminal 仅投递 event queue，由固定 owner tick 提交。删 domain admission/terminal 会让 callback 成为第二 writer；合并容量会互相饿死。 | `A-WORK`、`D-LOOP`；**Derived**。主循环与独立容量是义务，队列/worker 形状可替换。 | **Fact**：`ReloadableModelCatalog.ActiveScan`、`RuntimeContentStore`、`ClientModelRenderTargetManager.tick`、`ServerChunkRuntime.tick`；[有限工作理由](../../architecture/model-management/design-rationale.md#有限工作保持-domain-owned)。Exact session close 不 drain 共享 worker；进程 close 才结束对应长期 executor。 |
| MN-08 Required default 内存闭合与固定驻留 | Jar raw source 直接生成 resident memory container；客户端完成全部默认 render target，服务端完成本侧只读内容后才发布 required candidate。删闭合会让首次 fallback 变成另一项可能失败的加载；恢复临时文件会增加 handoff/清理。 | `D-DEFAULT`、`A-DEFAULT-MEM`、`D-FALLBACK`；**Essential**。 | **Fact**：`BuiltinModelCatalog.generateDefault`、`ManagedContainer.openResidentDefault`、`ClientModelRenderTargetManager.startRequired`；[默认基线](../../product-decisions/decisions/model-fallback.md)。旧临时 backing/delegate 机制与 builtin example 解压已退出；baked profile/cache 仍按 NR-05 独立处理。 |
| MN-10 Desired/installed 切换、当前意图与目标降级 | 每个 entity 独立保存当前 model/target/texture 意图；新 Ready 先安装再释放旧 lease，humanoid 兜底 default，其他替换恢复宿主。资源请求的 0.7 秒门槛只作用于当前缺件效果，fallback 不改权威选择。删协调会使短命选择发包、未完成 candidate 撤走旧表现或不同 entity 共用时间线。 | `D-FALLBACK`、`D-HOST-FALLBACK`、`D-GUI`、`A-CONTINUOUS-DEMAND`；**Derived**，目标结果与连续需求由产品决定，当前 binding 状态是实现方案。 | **Fact**：`EntityModelBinding.synchronize/installReady`、`ContinuousDemand`、`LocalPlayerDemand`；[失败与恢复](../../architecture/model-management/failure-and-recovery.md)。Selection 与 resource 分开推进；重复失败资格另归 MN-20。 |
| MN-11 Exact session、业务准入与迟到隔离 | 入队/应用核验 Connection；Hello 先经无状态开发版本门禁，ACCEPT transport commit 再建立稳定 `BusinessSession`，Selection、PlayerState 与控制消息不等待 catalog `ACTIVE`。协议失败/断连撤销业务资格，catalog failure 只关闭 publication/resource owner；publication/transfer 仍使用各自非零递增 ID，旧 terminal 不重开。删隔离会串服或把旧结果接到新会话；绕过版本门禁会让开发 wire 被稳定版策略误接纳；合并业务与 catalog 生命周期会让目录失败错误中断 gameplay。 | `D-SESSION`、`D-SESSION-FAIL`、`D-WIRE`；**Essential**，身份空间隔离与局部失败直接有产品依据。 | **Fact**：`VersionCompatibility`、`ClientModelSession.onServerHello`、`ClientSessionRuntime.beginConnection/businessSession/runIfCurrent`、`ServerModelService.runIfCurrent`、`ClientAssetTransfer`；`ModelSessionContractTest.differentDevelopmentProtocolVersionFailsOnlyTheModelSession` 断言失败保持 session-local。[session](../../architecture/network/transport-and-session.md)。门禁不新增协商状态或 wire；BusinessSession 不新增 wire identity，publication/transfer ID 仍存在，不能把表现路径的 generation-free 扩大成整个协议无 identity。 |
| MN-12 Typed admission 与业务局部 assembly | 各 request 保留自身 natural key、权限、coverage、optional terminal；整份 descriptor 先验证，再在 source acquisition 前建立既有 transfer owner。Preview 只用 slot/model/container 请求，以唯一 final range 动态定长并做 16 MiB/128 MiB 与媒体解码；icon/cover 保留 descriptor/hash。删验证会把半份/错权限结果当成功，给 preview 恢复 hash 则新增无依据版本 authority。 | `A-TYPED`、`D-CHUNKS`、`D-VALIDATE`、`D-ACCESS`；**Derived**，typed owner 是承载不可删验证义务、获取窗口与图片弱关联的方案。 | **Fact**：`ServerAssetTransfers.decodePresentation/validatePresentation`、`ClientAssetTransfer.PresentationChild`；[资产传输](../../architecture/network/asset-transfer.md)。没有晚绑定 callback owner；构造异常、enqueue reject 与 accepted close 仍归 MN-14。 |
| MN-13 仅超帧 action 的顺序 children | 完整 descriptor 超帧才顺序启动有限 children，父只聚合结果；取消阻止未启动项，先前 exact cache commit 不回滚。删 parent 会丢完整动作结果，总是逐项则增加 ID/终态。 | `A-FRAME-BUDGET`；**Derived**。 | **Fact**：`ClientAssetTransfer.MetadataAction/ModelAction`；[超帧理由](../../architecture/network/design-rationale.md#只有超帧-descriptor-才支付-parent-成本)。30 KiB 是当前架构预算，不是 Minecraft 硬性单包上限；提高预算不证明所有大动作都无需分片。 |
| MN-14 单一 accepted dispatch 与 range capability | Enqueue 是完整 packet 集合的 ownership frontier；global worker 持有 source、玩家 FIFO、cursor、限速/背压/retry 和 close，只构造当前有界帧。Bytes、chunk lease 与 file range 由一个 range packet 的三种 capability 解释读取和释放；拒绝或构造失败仍由业务 owner 关闭未转移能力。删除会扩大驻留、重复范围/终结、重复推进或双关闭。 | `A-DISPATCH`、`D-ADMISSION`；**Derived**。 | **Fact**：`RangePacket`、`ResourceDispatchWorker.enqueue/visit`、`ServerAssetTransfers.submit`；[dispatch 理由](../../architecture/network/design-rationale.md#accepted-resource-只有一个-dispatch-owner)。接纳时授权不因后续撤权重判；retry/cursor 不是第二套权限 authority。 |
| MN-15 Forced-selection 私有访问例外 | `ignoreGrants` 仅对当前 ModelId 生效，不写 grants/wire；撤权、切模、目录变化和重连维护此模式。删除会改变管理员强制选择下的资产取得。 | `A-FORCED`、根理由缺口 `H-FORCED`；**Uncertain** 产品必要性。 | 行为 **Fact**：`ServerModelSession.selectForced/canRequest`；`ModelSessionContractTest.forcedSelectionBypassesOnlyItsOwnChunksWithoutMutatingGrants`。Protocol/代码不能自行补写与 `RESTRICTED_AUTH` 的优先级，见 [Q-09](open-questions.md#q-09)。 |
| MN-16 Player projection 的真实基线与 best-effort 机会 | Reporter 先绑定握手后的 `BusinessSession`，自身 authority FULL 后才形成报告；该 FULL 在服务端 authority commit 后、collection publication 前发送。首个有效机会为 FULL，后续为变化 DELTA 或周期 FULL；观测在发送尝试前推进，失败不保留 dirty/待发/恢复。服务端只在成功应用 FULL 后建立 exact-session baseline，tracking 限定分发，Roaming 与瞬时 sync 分开。删真实 baseline 会接纳无上下文 DELTA；恢复 sequence/revision/generation 会重新引入无产品义务的顺序和完成协调。 | `A-REPORT`、`D-PLAYER`、`D-SERVER`、`D-TRACKING`、`D-SCRIPT`；**Derived**，表现同步是根义务，当前 best-effort 报告协议可替换。 | **Fact**：`PlayerStateReportPlanner`、`LocalPlayerStateReporter`、`ServerModelSession.acceptsPlayerStateReport/commitPlayerStateReport`、`PlayerStateHandler`；[玩家状态](../../architecture/network/player-state.md)。与 MN-02 保持 independent-authority；Unit seam 不证明真实 Forge handoff、peer receipt 或全部 replacement 交错。 |
| MN-17 Exact Flight interest 与迟到终态拒绝 | 未完成请求共享工作、分别持有 interest；最后 interest 消失先摘 exact Flight，再请求取消。旧 terminal 只能完成自身，不能覆盖同 key 的 replacement。删身份比较或取消协议会串接结果、误取消其他消费者或保留无需求下载。 | `A-RESOURCE`；**Derived**。只服务仍可能完成/取消的工作，不承担已完成资源回收。 | **Fact**：`ModelRenderTargetCache.acquire/cancelPending/finishSuccess`；[Pending 边界](../../architecture/model-management/ownership-and-lifecycle.md)。普通请求替换 offline Flight，离线 miss 不污染 normal acquire；失败 Flight 退出，诊断由 MN-20 等 domain owner 保存。 |
| MN-18 Sample-ready 纹理发布与 host ownership 移交 | Worker 成功只是 candidate；render owner 完成 base/PBR registration、upload 与 host adoption 后才提交 Ready。失败释放已注册 mapping 和未移交 component，成功后 target 只发一次 logical release。删门禁会把未可采样纹理暴露为 Ready；混用释放权会漏放或双重释放。 | `A-TEXTURE-PUBLISH`、`D-HOST`；**Derived**。旧表现不被失败 candidate 污染是义务，host 接纳前闭合全部 component 是实现边界。 | **Fact**：`HostTexturePublisher.publish`、`PublishedTextureBinding.close`、`ModelRenderTargetCache.finishSuccess`；[资源发布](../../architecture/model-management/ownership-and-lifecycle.md)。Minecraft/Iris 保有物理 mapping/GPU owner；完整实机 adoption 与回收仍待验证。 |
| MN-19 Ordinary publication 的延后 admission | Worker terminal 排队，在 render owner 每次 tick 按 4/2 个 ordinary terminal 处置；stale、失败和成功都计数，等待期间用 exact Flight guard 保活/拒绝 candidate。删除延后会集中执行 host 工作；只计成功会让失败 burst 绕过预算。 | `A-PUBLISH-BUDGET`；**Derived**，是 MN-18 的调度附属机制，required bootstrap 走立即完成路径。 | **Fact**：`ModelRenderTargetCache.acceptTerminal/enqueueAdmission/tick`；[所有权](../../architecture/model-management/ownership-and-lifecycle.md)。限额不等于 host upload 耗时或总 live bytes 上界，最坏合法负载仍缺成本数据。 |
| MN-20 Exact 失败记忆与显式重试资格 | Binding/domain 保存同 request/content 的 deterministic marker；只有显式 retry/reload 或相关内容、权限、连接、host 能力变化后再评估，切走切回与时间经过不恢复资格。同一 registry 还按 content identity + stage（TEXTURE/ANIMATION）+ resource 记 target 内 lazy 资源的读取失败：命中后动画读取直接回退 default，纹理失败使候选按内容错误被拒绝，access 与 content 失败都进入该 marker。删除会重复执行已知失败；扩大 marker 范围则可能永久阻断新内容。 | `D-RECOVER`、`A-FAILURE-MEMORY`；**Derived**。避免昂贵重复失败有产品依据，marker 粒度可替换。 | **Fact**：`EntityModelBinding.synchronize`、`ModelFailureRegistry.gate/hasMatching`、`ClientModelRenderTargetManager.resourceFailures`、`AnimationStore`、`RuntimeContentStore`；[失败与恢复](../../architecture/model-management/failure-and-recovery.md)。不保留失败 Flight，不与 preview miss 合并为全局表。 |
| MN-22 Remote cache 的物理路径约束 | 固定 hash 名仍需逐 sink 检查 physical root、目录 identity 与 no-follow handle；提交前复核目录，越界链接作为访问失败。只保留字面路径检查会把文件系统间接寻址误当成受控路径。 | `D-CAPABILITY`、`A-REMOTE-FILES`；**Derived**。远端能力受限是义务，当前文件型 cache 引入目录/链接检查。 | **Fact**：`RemoteModelStore.ownedPath/prepareOwnedDirectory/publishAtomic`；[物理存储边界](../../architecture/model-management/storage-and-cache.md)。这与 MN-05 的 bytes 完整性、atomic commit 分别解决不同失败，不能合并成一个“已验证”标记；全部 OS 竞态未验证。 |
| MN-23 共享派生 cache 的同 key writer 协调 | JVM key lock 与文件锁串行同 key materialize，取锁后重验，临时对象验证成功才 atomic commit；lock 使用计数在最后使用后退出 map。只删协调会允许 baked 模型与 baked 动画等实际消费者重复生产或并发处置同一 key。 | `A-SHARED-CACHE`；**Derived**。多个进程共用持久派生物是上游选择；remote、preview 与 direct source 不因此获得同一锁协议。 | **Fact**：`AtomicSharedCache.materialize/withKeyLock/acquireJvmLock/releaseJvmLock`、`BakedModelCache`、`BakedAnimationCache.loadOrBake`；[派生物存储](../../architecture/model-management/storage-and-cache.md)。Direct 副本消费者已退出；共用 helper 不等于可合并 identity、失效或清理语义。 |
| MN-24 Converted 消费登记与首次保守 prune | 参与进程用实际 OS 锁持续登记；新消费者只在 join/start 等待正在进行的短期清理许可，startup 不等。首次 scan 末尾按本次曾发布/使用集合 prune 一次，其他消费者存在或许可失败即跳过。删除登记会误删另一进程仍用对象；长期 PID/心跳恢复会增加新 authority。 | `A-CONVERTED-CONSUMERS`、`D-SOURCE`；**Derived**。跨进程共享与用户来源保护要求排除活跃使用，当前锁/一次 prune 是有限方案。 | **Fact**：`ConvertedCacheCoordinator.acquireConsumer/pruneOnce`、`ModelSystem.activateCatalog`、`ReloadableModelCatalog.ActiveScan`；[converted storage](../../architecture/model-management/storage-and-cache.md#converted-storage)。只管理 converted；不处理 preview/remote/baked，也不证明所有文件系统语义。 |
| MN-25 精确声音取得与统一表示保留 | Metadata-only source 在真实触发时按当前 representation/访问资格取得完整 verified stream；客户端用一个 64 MiB、30 秒 acquire TTL、访问顺序 LRU 账本保留 encoded 或完整短 PCM，正常短 EOF 以 PCM 原子替代 encoded cache 引用。删除 current-access 复核会让热 cache 越权；拆分账本会复制预算 authority；强制关闭已撤 cache 引用的 backing 会破坏活动播放。 | `D-SOUND`、`D-JOIN`、`D-CHUNKS`、`D-ACCESS`、`D-HOLD`、`A-AUDIO-RETENTION`；**Derived**。按需取得与安全共享不可删，具体账本/TTL/LRU 是当前选择。 | **Fact**：`SoundSource`、`ClientAudioRuntime`、`AudioRetentionCache`、`PlaybackAudioStream`；[客户端音频保留](../../architecture/model-management/storage-and-cache.md#客户端音频保留)与[音频生命周期](../../architecture/model-management/ownership-and-lifecycle.md#模型音频生命周期)。局部测试覆盖预算、TTL/LRU、热命中拒权、stop-vs-acquire 和 PCM 替代；真实 remote session、heap retaining path 与 GC/Cleaner 未验。 |
